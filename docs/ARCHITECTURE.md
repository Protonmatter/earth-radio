# Architecture

The 0.26.0 candidate adds native account ownership in Electron main. `auth-manager.mjs`
reuses the browser PKCE implementation with a main-owned redirect resolver;
`auth-callback.mjs` handles a bounded one-time loopback return and `auth-vault.mjs`
persists only OS-encrypted session ciphertext. `auth-ipc-policy.mjs` accepts the owned
top-level file document only. The preload and renderer adapter expose safe session
metadata plus the existing three-document read/CAS contract, without a generic token,
fetch or RPC channel. See [authentication operations](AUTHENTICATION.md).

Earth Radio has three deliberately separate execution boundaries.

## November 2026 candidate discovery and atlas

The maintained `discovery-core.js` module performs pure, deterministic station ranking and filtering; `discovery-ui.js` adapts that module to the existing runtime through explicit callbacks. The recovered runtime retains catalog loading, playback, navigation, persisted account state, metadata, and its successful-selection events. New filters transform its already-filtered station pool. The new `vector-atlas.js` draws locally bundled Natural Earth land geometry in the existing Leaflet map, replacing raster tile requests. Existing markers update their current payload and coordinates when a directory object changes. See [DISCOVERY.md](DISCOVERY.md) and [MAP_DATA.md](MAP_DATA.md). Historical paragraphs below describe the recovered baseline; this candidate replaces its CARTO basemap and simple similarity/random scoring.

## Public static web

Version 0.31.0 adds a finite same-origin directory reader under `/directory/`,
with demand-refreshed edge snapshots, ETags, stale fallback and validated mirror
discovery. It accepts only the named provider paths, never arbitrary visitor URLs.
Streaming avoids edge JSON normalization under the existing Free-plan CPU limit;
client normalization and UUID identities remain authoritative. See
[directory/search/map reliability](DISCOVERY_RELIABILITY.md). This does not publish
the desktop proxy or change the independent metadata quota/auth boundaries.

Area search now uses a maintained `map-directory.js` loader on explicit user
action, adding a bounded global mapped sample before the existing catalog filters
run. It reuses the runtime normalizer, retains richer existing source records,
fills missing coordinates and keeps cancellation/retry state local to the page.
The pinned-station fetch overlay leaves geo-only responses unchanged so it cannot
violate that loader's record budget. The directory action is radio-only and cannot
augment the SDR domain. See [DISCOVERY.md](DISCOVERY.md) for limits and semantics.

Cloudflare Pages, if later created, serves only the deterministic `.build/site` output produced from `site/`. The browser loads the station catalog and compatible HTTPS streams directly from public upstream services. No server code, Electron code, recovered TypeScript, tests, documents, source maps, local paths, or secrets are copied into the publish directory.

The service worker caches versioned application assets. Installation reloads maintained overlays so a new cache generation cannot be seeded from an obsolete browser HTTP cache, and it reuses the content-hashed runtime, CSS, and HLS bundles from the HTTP cache. If that install fails, the previous worker and cache remain active. `_headers` grants one-year immutable caching only to eight-character content-hashed runtime assets; maintained auth, responsive, and metadata overlays revalidate after five minutes. The staged-site validator rejects immutable caching inherited by any deployed non-fingerprinted file. Static hosting cannot bypass upstream CORS, mixed-content, codec, or station availability constraints.

Two additional maintained overlays load before the runtime bundle. `site/assets/storage-guard.js` hardens user-level persistence for favorites, recents, preferences, bad-station penalties, and last-played state. It reads those records, the active account, and the `earth-radio-storage-generation-v2` marker in one IndexedDB transaction. A valid marker makes the primary records authoritative even when they are intentionally empty; content emptiness is never interpreted as loss. Each healthy snapshot writes a checksummed, namespace-bound v2 envelope to a two-generation localStorage backup and advances the marker atomically with the IndexedDB snapshot. Recovery is considered only when the marker is missing or invalid, restores all protected records plus the exact backup generation in one transaction, and reloads only after commit, with at most two attempts per immutable namespace/generation in a tab session.

Storage namespaces are `default` when signed out and `account:<encoded user id>` when authenticated. Account transitions atomically archive and restore favorites, recents, preferences, bad-station penalties, last-played state, and the generation marker together; a backup for one namespace cannot restore into another. Legacy unscoped v1 backup data can migrate only into `default`, never directly into an authenticated account. `site/assets/directory-expansion.js` keeps the initial directory load bounded and expands coverage on demand: selecting a country (map "Explore", country picker, or country filter) adds its ISO code to `RADIO_CONFIG.featuredCountryCodes` — which the runtime re-reads on every directory fetch in both browser-direct and proxy modes — and triggers a refresh; expansions persist across sessions and apply before the first fetch. `site/assets/pinned-stations.js` asserts LISTEN.moe (J-pop and K-pop HTTPS MP3 fallbacks) into every directory payload and into a warm IndexedDB station cache so those two stations are not missing when Radio Browser omits them.


The runtime and overlays announce state transitions through semantic browser events rather than DOM inference (runtime changes are recorded as hardening overlays and mirrored in `src-recovered/main.ts`). `earthradio:station-selected` carries `{ streamUrl, stationUuid }` only after successful playback and preserves the canonical HTTP(S) station identity when MediaSource exposes a `blob:` URL or hls.js reattaches the same station. Only a correlated new selection or explicit clear invalidates that identity; same-station platform polls carry a monotonic generation so an older response cannot overwrite a newer one. `earthradio:country-selected` carries `{ country }` for pointer, keyboard, and programmatic picker selection. The runtime serializes and coalesces every boot, manual, retry, cloned, and directory-owned load behind one drain promise exposed by `earthRadioRuntime.refreshStations()`. `earthradio:stations-load-settled` carries `{ ok, loadId }` for each physical cycle. The directory overlay persists new codes synchronously, awaits its correlated runtime promise, and coalesces selections that arrive during a refresh into a follow-up using the latest country-code snapshot.

Map markers carry a Leaflet tooltip for progressive disclosure: hovering a station dot shows its name, country, and codec/bitrate before any selection happens, plus a best-effort now-playing line resolved through the live-metadata platform feeds (`docs/LIVE_METADATA.md`). Speculative tooltip lookups share `/api/nowplaying` with the playing-station poll and are capped at 8 requests per 60 seconds per tab, leaving room for the normal playing-station poll within the 30/minute shared per-IP budget. Multiple listeners or tabs behind one IP share that server budget. The tooltip binding is a minimal hardening overlay inside the hashed runtime bundle; its content and the async now-playing enrichment live in the maintained `site/assets/metadata-enrichment.js` overlay behind the `window.earthRadioMapTooltip` hook, so the bundle falls back to a name-only tooltip if the overlay is absent. `tests/e2e/` (Playwright, see `docs/E2E_TESTING.md`) covers this disclosure flow and the idempotency of repeated player actions hermetically.

An additive Atlas Editorial presentation layer (`site/assets/responsive-ui.css`, `site/assets/responsive-ui.js`, and `site/i18n/*`) loads after the recovered hashed runtime. `site/assets/ui-refresh.css` loads last and is presentation only: it re-ramps the shared custom properties, stands the header up as a desktop rail at or above 1100px, re-lays-out the station card inside the stride the virtualizer already fixes, and renders the quality tier as a four-bar meter. It adds no markup and no script, so removing its `<link>` restores the previous presentation exactly. The Atlas layer owns mobile destinations, Now Playing visibility, desktop split/collapse, and locale chrome. Catalog, playback, favorites, filters, metadata, and the Leaflet map remain runtime-owned. Presentation destinations persist in `earthRadio.ui.v1` and do not overwrite runtime `station`/`view` hashes. `data-i18n-attr` localizes only the named attribute so transport and header glyphs stay intact. The recovered virtualizer keeps its 168px cell height; mobile rows expose a 64px minimum and 44px play targets. Chinese locale IDs stay `zh-Hans` and `zh-Hant`. Electron’s minimum window remains 1080×720, so the desktop split is the Electron layout; mobile navigation appears only at or below 767px.

## Local Electron desktop

`electron/main.mjs` creates a sandboxed window with context isolation, Node integration disabled, navigation blocked, and external HTTP(S) links opened by the operating system. `electron/preload.cjs` exposes only the narrow proxy/configuration bridge required by the renderer.

The desktop process starts `server/desktop-proxy.mjs` on an ephemeral IPv4 loopback port and exposes API routes only beneath a cryptographically random per-launch capability path injected through the preload bridge. API requests require an allowed origin; the Electron `file://` renderer’s `Origin: null` is accepted only when that capability path is also present. Untrusted browser origins and unauthenticated raw-origin requests are rejected. Sandboxed file-renderer GET requests can omit the Origin header. The main process asserts `Origin: null` only for the owned webContents, the exact trusted file document, and that launch's loopback capability API prefix; existing Origin headers are never rewritten. `tests/smoke-desktop-renderer.mjs` exercises a real sandboxed file renderer and verifies that a raw originless client remains rejected. One pure binary policy shared with Pages classifies IPv4, IPv6, and IPv4-mapped, compatible, WKP, and legacy translated IPv6 forms. Private, loopback, link-local, multicast, unspecified, CGNAT (`100.64.0.0/10`), benchmarking, documentation, translation-local, Teredo, 6to4, discard-only, and IANA top-level address-space blocks marked Reserved by IETF are rejected; approved embedded forms remain allowed only when the effective IPv4 endpoint is public. DNS answers are validated and the connection is pinned to one approved result. The lookup callback preserves Node's array contract when the caller requests `all: true`, including on Node 24. `requestPublic` follows at most four redirects, resolves and revalidates every hop, destroys each redirect response before settlement, reacts to caller abort, and carries one absolute deadline through DNS, connection, redirects, and byte-capped body reads. This compensates for browser-only CORS limitations without creating a network-accessible open proxy.

Metadata identification is server-side. iTunes lookup needs no credential. Optional Spotify lookup reads credentials only from the process environment. Identification results are confidence-scored, explain reasons, preserve raw ICY metadata, and use a bounded in-memory cache.

Because raw ICY text is unreliable, higher-trust live-metadata feeds layer above it (see `docs/LIVE_METADATA.md`): hosting-platform now-playing APIs resolved from the stream URL, HLS timed ID3 read in the renderer, and opt-in on-demand audio fingerprinting (ACRCloud or AudD credentials from the process environment only; metered, rate-limited, cached). All radio-controlled proxy stream, playlist, segment, and platform fetches share the `server/net-guard.mjs` boundary and the original operation deadline. The independent generic Icecast/Shoutcast probes run concurrently inside one platform-resolution deadline and finish cleanup before returning. Fixed recognition-provider requests keep their configured destinations and separate abort timers.

`src-recovered/` is an older source snapshot selected from the hardened archive. It is useful for maintenance intent and domain logic but does not compile to the selected installed hashed bundle without the missing original toolchain/state. `docs/recovered/` has the same evidence-only status.

The selected runnable web, Electron, and server files came from the installed 0.24.0 application. `scripts/Import-EarthRadioRecovery.ps1` implements the selection rules and emits `docs/provenance/recovery-manifest.json`.

## Same-origin metadata functions (public web)

The public deployment carries two narrowly scoped Cloudflare Pages Functions under `functions/` (same origin as the site, not a separate service): `/api/nowplaying` (one-shot ICY StreamTitle read plus hosting-platform status resolution — keyless, byte- and time-budgeted, edge-cached) and `/api/track/fingerprint` (bounded direct/HLS audio sampling, active only when ACRCloud or AudD credentials are configured on the Pages project, and cached by normalized country plus stream URL). Browsers cannot read ICY metadata themselves, so without these the static web app has no live now-playing feed at all.

Both handlers send every listener-controlled URL through `functions/_shared/guarded-fetch.js`: only credential-free HTTP(S) targets are accepted; the shared binary IP policy blocks literal private, reserved, documentation, translation/transition, and other stable non-global targets plus the request's own origin; redirect handling is manual and every hop is revalidated; response bodies are byte- and deadline-capped. Alternate compressed, expanded, mapped, compatible, WKP, and legacy translated representations receive the same effective-endpoint decision. Because Workers cannot reproduce the Node resolver's DNS pinning, deployed production and preview environments must retain `global_fetch_strictly_public` from `wrangler.jsonc`, and repository validation rejects its removal or the addition of `global_fetch_private_origin`.

Rate enforcement uses private Durable Objects through Pages middleware before any metadata handler, including probes and cache hits. Per-client, per-environment rolling budgets are 30 now-playing and 6 fingerprint requests per minute, with non-extending 60-second mitigation. SQLite transactions persist bounded accepted-time queues across requests/isolates; alarms clear idle rows/storage. Object names hash the trusted Cloudflare client address plus a deployment-bound production/preview scope; no raw IP/account/stream is stored in counters. Missing identity/bindings or RPC failure returns 503. Rejections consume a Pages/DO invocation but trigger no station/provider work. This replaces the unavailable zone-WAF architecture; it is not a WAF invocation-cost shield. See [Cloudflare deployment](CLOUDFLARE_DEPLOYMENT.md) for Worker-first deployment, bindings, qualification and safe rollback.

## Excluded boundary: the desktop proxy stays private

The desktop proxy itself is still never published. Its directory federation, stream resolution/probing, and SSE endpoints would materially enlarge the abuse and SSRF surface and would require authentication, quotas, egress policy, logging, and abuse response. The Pages Functions above deliberately reimplement only the two read-only metadata lookups on the Workers runtime with their own guards; they do not import or expose the proxy.
